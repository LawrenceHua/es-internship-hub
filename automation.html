The automation inventory

Every automation has a job, a boundary, and a status. The boundary matters just as much as the job.

VERIFIEDINFERRED

How to read this inventory

Automation names and statuses are read from cited records. The classroom explanation of each boundary is a synthesis. A live row means the capability is active as described in its evidence, not that it can make every decision by itself.

Backend schedulers

These are in-process capabilities. Flag names identify the capability without exposing values.

One deliberately narrow predicate controls them all.

scheduler_flag_enabled() accepts only the literal string "true". Every flag defaults off, and nothing in the repository turns one on.

Flag-gated work
SchedulerFlagPurposeMust never doStatus
ml_improvement_scheduler.pyML_IMPROVEMENT_SCHEDULER_ENABLEDExport consented, adjudicated corrections to training storage each day.Export corrections without consent and adjudication.DARK
continuous_labeling_scheduler.pyAUTO_LABELING_SCHEDULER_ENABLEDLabel the review queue at a capped cadence.Put machine labels into the supervised training set.DARK
retrain_scheduler.pyRETRAIN_SCHEDULER_ENABLEDStart a one-shot trainer that writes non-served candidates.Serve a candidate automatically.DARK
recipe_reminder_dispatcher.pyRECIPE_REMINDER_EMAIL_SCHEDULER_ENABLEDSend owner-bound, custom-date reminder emails.Assume current runtime from source alone. Read /health/reminder-scheduler for the reminder runtime.FLAG-GATED
feedback_digest_service.pyFEEDBACK_DIGEST_SCHEDULER_ENABLEDPrepare a scheduled digest of feedback.Assume current runtime from source alone.FLAG-GATED

Notice the difference between the two statuses. DARK means built but not running in this release. FLAG-GATED means the code ships in the deployment and starts the moment its flag is set to "true" — with every flag defaulting off, the live state is a runtime readback at /health/reminder-scheduler, not an assumption from source.
