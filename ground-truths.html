Ground-truth catalogue

Fifteen facts the system measures for itself.

A ground truth is a fact the automation refuses to take on faith and instead measures. The card number is its ranking for student reuse, with the most portable idea first.

How to read the labels

VERIFIED

Read in the cited file, commit, receipt, or workflow.

INFERRED

A synthesis drawn from evidence, not a directly stored fact.

REPORTED

Stated in a lane report, without a public artifact to inspect here.

How each fact becomes a guardrail

Read each card from measurement to evidence, then from the incident that shaped it to the failure it prevents. The final line turns that mechanism into a small project you can reuse.

How it was formedOn August 8, 2026, local notes said the store listing was fixed while the live record still described a feature the build did not ship. Private product repository commit eb555954 recorded the correction and probe.

Student reuseTreat the second API call as the test. Re-fetch what you changed and compare every field that matters.

VERIFIED

What it measuresThe live store record through signed read-only requests, rather than through local documentation.

“Nothing here mutates ASC — the version PATCH and build attach are deliberately separate actions, because reading the state and changing it should never be one keystroke apart.”

How it was formedThe August 8, 2026 listing drift showed that a local file could be tidy while the outside system stayed wrong. Private product repository commit eb555954 kept the live probe beside the repair.

Student reuseBefore building on “we already have this,” write the smallest script that asks the live system.

RANK03

Refuse the wrong build at the parser

VERIFIED

What it measuresWhether the requested build is the one reviewed candidate, before any network call can begin.

“Bump this in the same commit that moves the release to a new build; R6's pin-uniqueness sweep checks this constant against every other pin in the repo.”

ios_apps/fastlane/asc/asc_presubmit_check.py

How it was formedRelease discipline tightened after the August listing incidents. On August 30, 2026, private product repository commit a57b9bf5 hardened the 4.3.4 submission path around one reviewed candidate.

Student reusePut the only allowed release value in code and reject every other value before work starts.

RANK04

Derive test counts from collection

VERIFIED

What it measuresThe exact tests the runner collects, their reviewed floor, passed count, and skip count.

“Every gated inventory below is DERIVED, never typed. Each file's expected count comes from a --collect-only pass over the exact selection the suite executes, so adding a test to a gated file can no longer red this job on a stale literal; the historical literal survives as <label>_floor, which still fails closed on shrinkage.”

.github/workflows/release-contracts.yml — the derived-count gate (B15, commit b0cdd703), quoted from source

How it was formedHand-typed totals became stale when tests were added and could stay green when tests disappeared. Private product repository commit b0cdd703 replaced them with counts derived from pytest collection on September 1, 2026.

What it makes impossibleA deleted test passing because the expected total was never measured.

Student reuseAsk the test tool what it found, then fail if that real count drops below the reviewed floor.

RANK05

Make the gate prove it found work

VERIFIED

What it measuresThe workflow must discover at least 99 gated files before it may report success, matching the floor recorded in the workflow itself.

“The first cut of this step used (^|[[:space:]]) as a leading anchor and extracted ZERO paths under the grep on the runner host, which without the floor would have been a green step that checked nothing.”

.github/workflows/release-contracts.yml

How it was formedOn August 18, 2026, a first-cut pattern extracted zero paths on the runner host. Private product repository commit 94c4305b recorded the near-miss and added the presence floor.

What it makes impossibleA green checkmark from a checker that silently inspected nothing.

Student reuseGive every checker a heartbeat assertion: it must prove that it discovered real work.

RANK06

RANK07

Let the runner write the receipt

VERIFIED

What it measuresWhether the release gate created a new, private, durable receipt instead of accepting one from the claimant.

“Every release mutation remains BLOCKED even if copied to the fixed install path.”

tools/shopper-release-runner/runner.c

How it was formedThe release boundary needed success evidence that a worker could not mint for itself. Private product repository commit 835b85ed added the fail-closed runner, authored August 21, 2026 (the committer date is August 22, 2026).

What it makes impossibleThe process asking for approval also manufacturing its own proof of success.

Student reuseMake the verifier, not the claimant, create the final receipt.

RANK08

Read consent back before data moves

VERIFIED

What it measuresWhether the server confirms the current opt-in and still grants live consent at the moment of a training write.

“A stored user_consented_upload bit is only historical evidence that a copy was permitted at capture time; it is not authority to adjudicate or export after the shopper withdraws consent.”

backend/server/services/training_consent.py

How it was formedA cached preference could echo an old opt-in and resurrect withdrawn consent across devices. Private product repository commit 3be85e17 closed that path on September 1, 2026.

What it makes impossibleUsing data after the person withdrew permission.

Student reuseTreat “yes” as perishable. Re-check permission at the exact moment you use the data.

RANK10

Make publication fail closed

VERIFIED

What it measuresThe published file hashes, source-tree digest, approved copy registry, expiry dates, and forbidden claim patterns.

“There is deliberately no auto-approve/update mode.”

verify-publication.js

How it was formedThe August 2, 2026 public-claim audit followed August overclaim incidents. Related private product repository commit eb555954 recorded the live listing mismatch on August 8, 2026.

RANK11

Make feature flags fail closed

VERIFIED

What it measuresOnly the literal string true enables irreversible automation, while unreachable remains unknown rather than off.

“A timeout is never a pass and never ‘the flag is off.’”

backend/server/tests/test_fridge_condition_health_stage.py

How it was formedA runtime setting could contradict the store promise without a source change. Private product repository commit c0908ee3 closed a fail-open scanner mount on August 17, 2026.

What it makes impossibleA typo, alternate truthy value, or unreachable service silently turning a risky lane on.

Student reuseDefault to off, accept one exact enabling value, and keep “unreachable” separate from “disabled.”

RANK13

Refuse starved training classes

VERIFIED

What it measuresEvery model head has supervised rows, and every evaluation class has at least 40 examples per split.

“Training is refused rather than completing with a head that received no gradient.”

scripts/train_capture_multitask_b4.py

How it was formedCommit 9b259f7c records the defective run dated August 11, 2026: 170,817 rows silently resolved to a sentinel and the quality head took no gradient for eight healthy-looking epochs, while all 1,072 “degraded” records sat in train so validation and test could not see them. Commit d22d2436 on September 1, 2026 added the degraded-class refusal and pinned its floor in a test; the trainer now refuses to complete with a head that received no gradient.

What it makes impossibleA model checkpoint advertising a skill that it never practiced or evaluated.

Student reuseCount examples per class and split before you calculate accuracy.

RANK15

Say what a receipt cannot prove

VERIFIED

What it measuresThe exact provenance binding a receipt claims, plus the binding it explicitly does not claim.

“A file cannot truthfully contain the hash of a future commit that contains that file.”

.design-factory/evidence/inventory-selection/inventory-selection-repair-receipt.json

How it was formedEvidence hardening exposed a circular promise: a receipt cannot contain the future hash of the commit that will contain it. Private product repository commit d42baaf7 recorded the honest boundary on August 15, 2026.

What it makes impossibleFabricated provenance or a historical result quietly being relabeled as current.

Student reuseAdd a “not checked” field to every report. It is often the most trustworthy line.
