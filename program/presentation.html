The 9/10 presentation: how the business runs itself

One owner, one product, no employees. Seven stations fire on schedules and leave evidence a skeptic can re-check, and four decisions stay with the owner on purpose. This page is the deck; every station names what fires, what it must never do, and where the evidence lands.

How to read this deck

Station facts are read from cited records on the owner's machine and in the private product repository, so they carry the REPORTED label: a reader cannot open the primary source from here. The closing contrast, what the machines do versus what the owner still decides, is a synthesis and carries INFERRED. Status chips tell live from dark: LIVE means the capability is firing as described in its evidence, DARK means built but not running, and nothing dark is ever implied to be live.

Seven stations, in the order the talk tells them

Each station names what fires with its real cadence, the boundary it must never cross, and the record it leaves behind. The order is the story order, not a data-flow diagram: marketing first because it is mostly dark, and that is the first lesson.

STATION01

Marketing

DARKLIVE

REPORTED Station snapshot observed 2026-09-04. See the inventory for the latest machine reading.

The honest station. The marketing-posts row in how it works is a human-approved queue marked in development: nothing in it fires by itself. A LinkedIn poster lane exists at ~/es-ops/marketing/linkedin_queue_runner.py, but its launchd plist is not installed. A daily expiry-email digest (EM1) is built and blocked unmerged behind a default-off flag. The one live growth-adjacent signal is the Monday heartbeat to #es-growth, and that is a monitor, not marketing output.

What fires

The Monday heartbeat to #es-growth. Everything else waits: designed, gated, and dark until the owner turns it on.

Must never

Post without owner approval, or let a default-off flag flip itself. Fail-closed defaults are the lesson, not the embarrassment.

Evidence lands

~/es-ops/marketing/, the how-it-works marketing row, and the Monday heartbeat line in #es-growth.

STATION02

Feedback

LIVE

REPORTED Station snapshot observed 2026-09-04. See the inventory for the latest machine reading.

Shopper feedback and scan corrections land in the production database. Every morning, launchd com.lawrencehua.es-feedback-digest (daily 09:15) runs ~/.openclaw/tools/feedback_digest/feedback_digest.py, which pulls /feedback/unreviewed and /scan-feedback/admin/corrections from production and posts the queue to Slack #es-daily. The first live run was observed 2026-09-04 at 09:35 ET. From there the routing is human: digest to owner brief in es-ops/briefs to pull request. Scanner corrections also feed the ML loop, flag-only per the owner's 2026-09-03 decision.

What fires

feedback_digest.py via launchd, daily 09:15, posting the unreviewed queue to #es-daily.

Must never

Open a pull request or apply a correction by itself. The digest reports; a person routes.

Evidence lands

The #es-daily post and ~/.openclaw/workspace/memory/feedback_digest/.

STATION03

The ML system

LIVE

REPORTED Station snapshot observed 2026-09-04. See the inventory for the latest machine reading.

A flywheel, not an autopilot. The flywheel steward (launchd com.lawrencehua.es-flywheel-steward, daily 09:05, ~/system-map/comms/es_flywheel_steward.py) watches the QUALITY, STORED, DEPLOYED, and ACTIVE axes, posts to #es-daily, and writes ~/system-map/_data/es-flywheel/steward-latest.json. A dead-man heartbeat (daily 12:15) watches the steward itself. The mesh bridge (daily 09:35) turns findings into gated draft fix cards and never auto-applies them. Retrain gates are on-demand with auto-promote off by owner decision, and a serving canary probes the content gate every 30 minutes.

What fires

Steward 09:05, dead-man heartbeat 12:15, mesh bridge 09:35, serving canary every 30 minutes.

Must never

Apply its own fix card or promote a model. Findings become drafts; a person decides.

Evidence lands

steward-latest.json, the #es-daily posts, and the heartbeat watching the steward.

STATION04

Development

LIVE

REPORTED Station snapshot observed 2026-09-04. See the inventory for the latest machine reading.

Every pull request runs the required checks release-contracts and asc-gate-tests, plus shopper-tests on iOS paths, on five self-hosted runners on the studio Mac. Test counts are derived from collection, not typed by hand, so a deleted suite fails the gate instead of shrinking it. Overnight, a Sauce real-device matrix runs nightly at 23:17 and an accessibility monitor runs daily at 08:47.

What fires

Required PR checks on every push, the 23:17 real-device matrix, the 08:47 a11y monitor.

Must never

Pass with a deleted suite, a hand-typed count, or an unverified toolchain.

Evidence lands

The check run on each pull request and the nightly device summary record.

STATION05

Backend and releases

LIVE

REPORTED Station snapshot observed 2026-09-04. See the inventory for the latest machine reading.

The Fly release is protected: .github/workflows/fly-deploy.yml builds once, checks a canary with a signed probe, and promotes the exact same registry digest, and only the owner can dispatch it. The App Store chain is deliberately gated: the fastlane signing and upload lanes are tombstones (Fastfile: upload_shopper_candidate_gated and friends), the real authority is a local root-helper runbook, and release_readiness_gate.py blocks Submit until every precondition reads true. An ASC verdict watcher polls every 30 minutes, and a daily release dry-run at 07:00 exercises the whole path without authority.

What fires

Owner-dispatched Fly releases, the 30-minute verdict watcher, the 07:00 dry-run that proves the path without using it.

Must never

Rebuild between canary and production, or submit without the readiness gate. Tombstones must never run.

Evidence lands

The dispatch receipt, the promoted digest, state/es-asc-verdict-latest.json.

STATION06

Frontend and this hub

LIVEREPORTED

REPORTED Station snapshot observed 2026-09-04. See the inventory for the latest machine reading.

The hub eats its own cooking. Two producers, emit_automation_inventory.py and emit_release_state.py, read the machine and regenerate the inventory and release-state blocks; they are human-run by design and say so on the page, which is why they carry REPORTED. The validate.yml workflow runs the ledger, site, and page gates on every pull request, the ledger evidence rule binds claims to receipts, and a salted-digest denylist keeps banned names out of copy.

What fires

validate.yml on every pull request; producers regenerate blocks when the owner runs them.

Must never

Report completion without an anchor, or pass a check that found nothing.

Evidence lands

This repository: generated blocks with stamps, the ledger, and the checks named on ARCHITECTURE.md.

STATION07

Ops monitoring

LIVE

REPORTED Station snapshot observed 2026-09-04. See the inventory for the latest machine reading.

The robots that watch the robots. A supervisor heals five enumerated stale jobs every 900 seconds, with an audit record per heal. A health fingerprint and KPI watch run every 30 minutes and post to #es-incidents only on a state change. A production smoke probe fires daily at 09:20, the overseer digest lands in #es-daily at 08:40, a 03:30 job consolidates the day's learning, and the @Expired Slack bot, live since 2026-09-04, answers intern questions grounded in immutable repository snapshots.

What fires

Supervisor every 900 s, fingerprint and KPI every 30 min, smoke 09:20, overseer 08:40, dream 03:30, the bot on mention.

Must never

Heal silently without an audit trail, or alert on an unmeasured claim.

Evidence lands

#es-incidents on change, #es-daily digests, and the bot's snapshot-grounded answers.

INFERRED

What a human still does

The punchline of the talk. Every station above ends at one of four decisions, and none of them is scheduled:

Merge

Gates can refuse a pull request forever; only the owner merges what passed.

Release

The deploy workflow does not run until the owner dispatches it, pinned to one build.

Promotion

No model, fix card, or flag ever promotes or flips itself. Auto-promote is off by decision, not by accident.

Marketing approval

Every post waits for a human OK, and the lanes stay dark until the owner switches them on.

The contrast to land on

The machines measure, digest, gate, rehearse, heal, and prove. The owner decides. That is what "automated end to end" actually means here: a paper trail written by machines, closing in on four decisions a person makes on purpose.
