Job in the loop

Apply rules between screen and record.

The private application tree uses a Python FastAPI surface with routes, services, repositories, middleware and a centralized database lifecycle. The architectural idea matters more than endpoint count: the backend is where a user action becomes an authorized, observable operation.

Source capability
Routes, services, middleware, repositories and release workflows exist in the current default-branch source.
Runtime evidence
The source contains more than one historical or candidate hosting path. Only a current deployment readback can identify installed code.
Human gate
The release workflow is manually dispatched. A push or passing source test is not deployment approval.

Automation and tests

Prove the path in layers.

  • Source contracts cover routes, middleware and database behavior.Representative tests exercise request bounds, authentication and persistence without proving the production service is reachable.
  • Release checks bind a candidate before promotion.Default-branch workflow tests and release-contract checks protect configuration; the running artifact still needs a digest and health reading.
  • Canary and production are distinct.A canary response is evidence for that candidate environment only. Promotion requires its own authorized action and readback.

Critical boundary

Source is not the running server.

A repository can describe several futures at once. Configuration, disabled workflows, legacy adapters and active code can coexist; runtime provenance resolves which bytes actually serve requests.

Never inferA clean branch, green unit suite or workflow file does not prove deployment, database connectivity or semantic delivery.
RequireExact source SHA, built artifact identity, canary result, authorized promotion and post-release health plus behavior checks.
