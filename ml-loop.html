The ML loop today

This is a deliberately incomplete loop. The live safeguards are visible; the irreversible pieces remain dark or offline.

VERIFIED

Five stages with different permissions

The labels distinguish a running safeguard from a built capability that is deliberately not running.

LIVE

Consent captured

PhotoTrainingConsentView.swift starts off and presents equal-weight accept and decline choices.

LIVE

Consent read back

UserSettingsService.swift requires the server to acknowledge the same local choice.

LIVE

Eligibility

training_eligibility.py accepts only server-adjudicated human review for training rows.

DARK

Schedulers

Export, auto-labeling, and retraining are built behind flags that default off.

OFFLINE

Promotion

model_promotion_lock.py supports a human-gated path, never an automatic one.

Notice that consent is checked before data can move, while the steps that could change a model remain separated from automatic operation.

REPORTED

What is being built next

The self-improving loop is designed and in build behind flags that default off. It is not presented here as a live feature.

INFERRED

The ethic in one paragraph

Consent is treated as a living fact, not a checkbox: captured before use, echoed to the server, checked again when needed, honored across devices, and revoked with deletion. The dangerous half of the loop can be built while promotion to people stays human. The moral rule is encoded in leases, tombstones, and filters in training_consent.py, not left only in a policy document.
