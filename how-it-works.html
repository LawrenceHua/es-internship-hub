02 · BACK END

One API, plus its stunt double

A Python (FastAPI) server in the cloud answers every app request. Next to it lives an identical twin used to rehearse releases safely.

☁️

Production API

Auth, rate limits, budgets, and every answer the apps show.

in: app requestsout: JSON answersruns: 24/7

Canary twin

Every new release must prove itself here first. Sleeps when unused.

in: candidate buildsout: pass / failruns: on release days
03 · AI

The AI names your food. It never guesses freshness.

Today a vision model identifies what's in the photo — identification only. Freshness comes from data, not from a guess.

🧠

Vision AI

Looks at the photo, returns food names. Third-party today; in-house models are being evaluated to take the lead, with the third party as backup.

in: photoout: "milk, lettuce, eggs"runs: per scan
🔬

The evidence gate

An in-house model ships only after passing hard safety tests — like almost never calling spoiled food fresh.

in: candidate modelout: ship / not yetruns: before any launch
🤝 The honesty rule: if we can't back an answer with data, the app says "we don't know" instead of making something up. That rule costs us features — and it's why you can trust the ones we keep.

06 · THE ROBOTS

The automations in between

Nobody has to remember to check anything. Each robot has one job, a trigger, and a place it reports to.

🚀

Release robot

A human approves and starts every deploy — the robot builds it, rehearses it on the twin, and undoes any failure automatically.

trigger: one approval
build once → rehearse on the twin →
same build to production →
any failure = automatic undo
🛡️

Gatekeeper

Blocks any pull request that fails a test — unit suites, release contracts. No exceptions.

in: every push/PRout: green or blockedtrigger: each push/PR
🍎

Store watcher

Watches the App Store review status so nobody refreshes a dashboard.

out: chat alerttrigger: every 30 min
🩺

Health watcher

Runs 7 real checks every 30 minutes — production health, the canary twin, App Store watcher freshness, backups, domain status — and pages a human when something changes.

out: page a humantrigger: every 30 min
coming next → a robot that watches the robots
🧍 What stays human, on purpose: approving a release, publishing anything public, and the App Store launch button. The robots do everything up to the decision — the decision stays with a person.
