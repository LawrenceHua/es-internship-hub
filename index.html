Get started — do this on Monday

This week the whole team builds FreshLens in one shared repo. It already runs out of the box — your job is to get it running, claim a slice, and ship your first pull request the AI-native way. Everything below is in the starter repo.

  1. Clone & set up — about 15 minutes. One command makes the virtual environment, installs everything, arms the safety guardrails, and runs the tests. git clone https://github.com/LawrenceHua/es-intern-freshlens.git cd es-intern-freshlens ./setup.sh # venv + deps + Claude Code hooks + self-test
  2. Run it and look around. uvicorn app:app --reload # then open http://127.0.0.1:8000 In Claude Code, run /onboard and read GETTING_STARTED.md. New to Claude Code? Read docs/USING-CLAUDE-CODE.md first.
  3. Claim a starter task. Pick one good first issue (one per slice: detect · freshness · act · frontend · report · eval, plus an optional future provenance-research reference), then claim it — this also creates your branch: gh issue develop -c <issue-number>
  4. Build with AI, then ship. Work only in your files. Explore → Plan → Implement → run /code-review → open a pull request. CI (lint, tests, secret-scan) must pass and one teammate approves before it merges. Never push straight to main.
3 non-negotiables: keep the API shape {"status":"ok","data":…} · never commit secrets or a .env file · stay in your lane and leave pytest green.

Do this before Friday

  1. Start from integrated main. Pull the repo, run the app, and run pytest. If someone reports a different test count, write down the branch they ran. The team ships from main.
  2. Trace one scan through the system. Follow one image through /api/scan/detect, src/detect.py, src/freshness.py, static/app.js, and /api/scene/act. Each intern should be able to explain the JSON shape.
  3. Exercise the trust loop. Save a provenance receipt, verify it, change one character, and verify that it fails. Write down exactly what it proves: issuer, timestamp, and no tampering. Also write down what it does not prove: the returned item is physically the same item.
  4. Write a one-page opportunity brief. Compare FreshLens against surplus marketplaces, markdown optimization tools, digital receipts, QR / GS1 traceability, and blockchain provenance. End with one recommendation: build now, stretch later, or do not pursue.
  5. Turn the decision into issues. By Friday, every Week 4 task should have an owner, a small file scope, a demo expectation, and a regression test expectation.
